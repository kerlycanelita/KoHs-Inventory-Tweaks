## Findings and changes

1. **Fast fresh presses were merged.** The controller treated exactly two presses
   as one when a poll interval was at most 25 ms. GLFW already distinguishes
   `PRESS` from `REPEAT`; the frame interval is not evidence of hardware chatter.
   Two genuine presses could leave the inventory open. Removed the time-based
   heuristic: counted, owned presses retain open/close parity at every frame rate.
   Ambiguous or shared-binding queues still fall back to Vanilla unchanged.

2. **Held mouse input always disabled fast opening.** `activeButton != null`
   selected the tick-based path even when the original button action had already
   been consumed. Added `fastInventoryWhileMouseHeld`, off by default and on in
   the PvP/performance presets. It keeps the complete-poll and queued-action
   conflict checks. Vanilla's new screen starts with `skipNextRelease=true`, no
   clicked slot and no quick craft operation. No extra inventory click is created.
   Enabling it warns that opening earlier can interrupt a sustained world action
   earlier; players who prefer the old timing can leave it off.

3. **Shortcut targets came from the previous rendered slot.** Vanilla updates
   `hoveredSlot` in `extractContents`; keyboard swaps/drop and mouse-bound hotbar
   actions can read it before the next render. Added `immediateSlotTargeting`, on
   by default. Resolve the current delivered pointer immediately before the
   ordinary shortcut handler, mouse-bound handler or bundle scroll. Use Vanilla's
   private hit test, including its recipe-book occlusion, and preserve
   `onStopHovering` cleanup. Keyboard/scroll coordinates are transformed once;
   mouse-button coordinates are already transformed by the existing click path.
   Scope is the ordinary player inventory, not custom subclasses or creative UI.

4. **Repeat suppression was coupled to acceleration.** Added the independent
   `suppressInventoryKeyRepeats` switch. It filters only `GLFW_REPEAT`, retains
   fresh presses and releases, and retains existing text/search/shared-binding
   exceptions. This is an optional behavior change from Vanilla's hold-to-repeat.

5. **The animation label promised too much.** Renamed it to reducing visual
   motion. It does not speed up clicks, close callbacks or server transactions.
   Kept a concise warning about frozen progress/recipes and hidden enchantment
   glint, because those are real usability tradeoffs.

6. **The tweaks page could truncate its explanation and ignore Escape.** Grouped
   controls into Response, Cursor and Visuals. Cards have a clipped scrollable
   viewport, wheel/arrow navigation, stable toggle positions, dependency-aware
   enablement, explicit state and named narration. The last-open explanation wraps
   over three reserved lines. Escape returns from the page. Changing a setting
   updates the active preset to Custom and persists through the existing store.

Closing still runs through Vanilla's `onClose`/`LocalPlayer.closeContainer` path;
no duplicate close packet, client tick, cooldown removal, key replay or global
mouse-sensitivity modification was introduced. Fresh physical input is not
delayed for animations. This audit does not claim that every report of slow
closing has the same cause: a stalled frame can delay dispatch before the close
callback starts.

## Version comparison

The 26.1 and 26.1.1 baseline input controllers and relevant mixins match root
26.1.2 byte-for-byte. 1.21.11 has focus/API differences; 26.2 moves screen/overlay
ownership to `minecraft.gui` and changes render methods. All four inspected
version controllers contain the same 25 ms merge heuristic and held-button gate.
Their current shortcut paths have no current-pointer refresh. Their source must
be ported with their own mappings and injection sites, not by copying the new
26.1.2 mixin blindly.

## Input and performance boundaries

The pointer remains OS-controlled inside the inventory. GLFW documents that raw
mouse motion is provided only in disabled-cursor mode; the inventory releases
that mode. Cursor Landing improves the starting position, not ongoing sensitivity
or the hardware polling rate. See the [GLFW input guide](https://www.glfw.org/docs/latest/input_guide.html#raw_mouse_motion).

The new slot lookup runs on an actual unconsumed key, side-button shortcut or
scroll event, not every mouse-motion sample or every frame. It uses the existing
small slot list with no new per-slot allocation. Removing the merge heuristic
also removes the unconditional per-frame timestamp read from the fast controller.
No claim of a specific FPS or millisecond improvement is made without a hardware
measurement. See [Fabric's 26.1 guidance](https://www.fabricmc.net/2026/03/14/261.html)
for the unobfuscated/Java 25 transition.

## Validation

Commands and the runtime fixture are documented in
[`tools/qa/pvp-input/README.md`](../../tools/qa/pvp-input/README.md).
Runtime and final validation results are recorded after the run below.

The final 26.1.2 run used the rebuilt `1.0.11+mc26.1.2` JAR and completed the
development PvP input macro with `checks=217; failures=0`. It emitted
`MACRO_COMPLETE macro=pvp-input; screen=none` and no `PVP_INPUT_FAIL` or
`MACRO_ABORT`. The close callback was observed at 6,168 microseconds in that
run. The client and integrated server exited normally after the macro.

Final static checks passed after the version bump: the root Gradle build,
translation validation (288 referenced keys and 382 entries per language), and
all 76 root mixin member references, 32 injector signatures, and 10 `INVOKE`
points resolved against the 26.1.2 client.

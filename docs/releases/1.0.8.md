# KoHs Inventory Tweaks 1.0.9

## Supported builds

- Minecraft 1.21.11, 26.1, 26.1.1, 26.1.2, and 26.2.
- Fabric client-side mod.
- 1.0.8 remains available for the previously published targets.

## Final five-version alignment

- Ported the current 26.1.2 cursor, input, scale-scope and persistence fixes to
  1.21.11, 26.1, 26.1.1 and 26.2 while retaining each version's own GUI API.
- Added the missing 26.1.1 release target and kept its exact Fabric/Minecraft
  dependency metadata.
- GUI Scaler now returns an identity transform whenever it is disabled, so the
  selected container preview and real containers cannot inherit a global GUI
  scale accidentally.
- Packaged the MIT license text in every target JAR and pinned the disposable
  debug companion to the exact release JAR during local QA.

## Input changes

- The inventory no longer opens early while a mouse button is still held. A held
  button was pressed against the world and its release is still to come; opening
  first handed that release to a screen that did not exist when the press
  happened, losing the world action it belonged to. The check reads
  `activeButton`, the one field Vanilla assigns on both edges.
- Two inventory presses inside one GLFW batch now open once instead of not at
  all. A batch is a single rendered frame -- eight milliseconds at 120 fps --
  which no hand produces and a worn switch produces constantly.
- A press handed to Vanilla stays handed over. Frames run far faster than the
  20 TPS tick that drains Vanilla's click queue, so a yielded click was still
  queued several batches later and any later press let the early path reconsider
  it.

## Compatibility

- Any confirmed overlap with another mod now disables the affected feature
  outright, whatever its severity. When two mods write the same thing the result
  stops being predictable from either one's code. The issue is still published,
  so the Issues Tracker still names the mod that took over and why.

## Cursor and scaling

- Cursor landing is finalized when `setScreen` returns rather than from
  `Screen#init`, which also runs on every window resize and could re-arm the
  landing long after the opening. This removes the later correction that players
  perceived as the cursor being dragged back.
- The container title key is folded to lower case when classifying, the way the
  scale classifier already folded it, so both agree on the same screen.
- Scaled containers receive the drag delta in the same space as the drag
  position. A widget reading the delta was being handed screen pixels next to a
  surface point.

## Minecraft 1.21.10

- Fixed a start-up crash. `AbstractContainerScreen#renderSlot` takes
  `(GuiGraphics, Slot)` on this version, and both item-highlight injectors
  declared `mouseX` and `mouseY` as well. Mixin refuses that descriptor when it
  applies, and it applies on class load, so the game died the moment anything
  loaded a container screen. The defect was already published.
- Added the inventory warm-up that the other targets already had. Measured at
  27.9 ms of class loading and surface composition moved off the first press,
  against 15.8 ms on 26.1.2 -- more than a whole frame at 60 fps.
- Cursor landing keeps the previous one-shot design on this target. Its
  controller cooperates with Raw Input Buffer by cancelling that mod's
  `centerSystemCursor`, which the newer targets no longer do because the
  compatibility yield covers it.

## Client trust boundary

- No custom networking channel or custom inventory packet is used.
- No slot click, offhand swap, hotbar selection, cooldown, or server-confirmed
  state is executed by the fast-open controller.
- The diagnostic stress macros live only in the separate debug companion and are
  not included in these release JARs.

## Player reports

### Center Mouse Fix felt heavy

Players turned Center Mouse Fix off because moving the pointer toward a totem or
any item right after pressing the inventory key felt weighed down. The cause was
the timing of its check: it ran after `Screen#init`, so a pointer the player had
already started moving looked misplaced and was put back.

The check now runs inside `releaseMouse`, right after GLFW leaves
disabled-cursor mode. That is still early enough to catch the case it exists
for, a pointer GLFW restores to a stale position after a window resize, and it
happens before the player can have moved. A pointer that moved after the
release is never touched again.

### The inventory sometimes opened late

Super Fast Inventory waited for the next client tick, up to 50 ms, more often
than it had to:

- A pending offhand swap, drop or pick-block click no longer makes it wait.
  Vanilla handles those after the inventory in the same tick and the opening
  discards them anyway, so waiting only delayed the screen.
- A held mouse button no longer sends every opening to the tick on 26.2, 26.1.1,
  26.1 and 1.21.11.
- It still waits when Vanilla would run something first: a hotbar or other key
  handled before the inventory, a pending attack or item use, an item in use
  (shield, bow, food) or a block being broken. The line under the option names
  the reason whenever an opening waited.
- After an early opening the attack miss penalty is cleared, as the tick-time
  opening clears it.

## Interface

- **Silhouette glow.** Player Visibility draws a soft glowing rim around each
  normally visible player instead of brightening the model. It is depth-tested
  like the body: blocks hide it, and Minecraft's through-wall glowing outline is
  never used.
- **Player Visibility page.** A live world view sits beside the inventory
  preview; the duplicated header is gone and the page fits at GUI scale 2, 3
  and 4.
- **Hover descriptions.** Option cards show only their name. Hovering explains
  the option, and for Super Fast Inventory, Center Mouse Fix and Reduce
  inventory visual motion it plays a recorded Vanilla-versus-KoHs clip made
  with the same input on both sides.

## Every version at the same level

26.2, 26.1.1, 26.1 and 1.21.11 now carry the complete 26.1.2 feature set,
including what 1.0.11 and 1.0.12 had only shipped for 26.1.2:

- the PvP response options (fast opening with a mouse button held, one toggle
  per key press, immediate slot targeting) and the grouped settings page;
- the contact-bounce collapse, the fix that stops a second mapping on the
  inventory key from disabling fast opening, and the config schema stamp;
- whole-surface container scaling and the new tab icons.

On those versions **Remove absolutely all inventory animations** becomes
**Reduce inventory visual motion**, as it did on 26.1.2 in 1.0.12: progress
indicators, recipe choices and enchanted-item glint stay Vanilla's. The saved
setting carries over.

## Vanilla and network boundary

Opening and closing stay on Vanilla's paths. The release adds no packet, replays
no key, removes no tick and changes no server transaction, cooldown or mouse
sensitivity. Server-controlled screens keep their Vanilla timing.

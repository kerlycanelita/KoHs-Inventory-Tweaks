# KoHs Inventory Tweaks 1.0.7

## Supported builds

- Minecraft 1.21.11, 26.1, 26.1.1, 26.1.2, and 26.2.
- Fabric client-side mod.

## Performance and input changes

- Added a once-per-world inventory warmup. It loads the player inventory screen class, recipe-book path, selected inventory texture, and composed custom surface before the first real inventory press. The warmup never opens a screen, changes a slot, moves the cursor, or sends a packet.
- Restored the reduced Super Fast Inventory path. A sole physical Inventory press can open the ordinary local player inventory after the current GLFW input batch rather than waiting for the next 20 TPS client tick.
- Preserved Vanilla ordering whenever another non-movement action shares the batch or remains queued. Offhand, hotbar, attack, use, drop, pick, and other screen actions are never consumed, deferred, retried, or synthesized by KoHs.
- Added a configuration readout that reports whether the latest open was immediate or fell back to Vanilla because a named key binding shared the batch.
- Added item-following Cursor Landing for the player main inventory and hotbar. The item is selected from the player's main hand; the offhand, armor, crafting, and result slots are excluded.
- Resolved item-following landing before the screen becomes visible, removing a possible second cursor placement. Cursor placement remains one-shot with no interpolation, verification loop, or continuous pull.

## Interface and compatibility

- Removed the obsolete Profiles and Smart Highlighter entry points from the configuration interface while preserving safe migration of older configuration files.
- Kept the 200% default inventory scale and Affect All Containers enabled for new installations.
- Retained English as the fallback language and Spanish translations for every supported Spanish locale.
- Kept the Herzium integration removed. KoHs neither inspects nor modifies Herzium.

## Client trust boundary

- No custom networking channel or custom inventory packet is used.
- No slot click, offhand swap, hotbar selection, cooldown, or server-confirmed state is executed by the fast-open controller.
- The server may observe only later ordinary Vanilla actions performed by the player after the locally visible screen opens.
- The diagnostic stress macros are distributed only in the separate temporary debug companion and are not included in these release JARs.

## Validation

- All five clean Gradle builds completed successfully.
- The remapped JARs declare an exact Minecraft version, client-only environment, and the correct `1.0.7+mc...` artifact version.
- Deep bytecode verification resolved every mixin target and injection point: 60 member references and 8 `INVOKE` points on 1.21.11; 63 and 9 on 26.1/26.1.1/26.1.2; 62 and 9 on 26.2.
- A development-only offline 26.1.2 singleplayer run completed without a crash. The aggressive debugger suite recorded 212/212 successful inventory openings, 0 open misses, 0 assertion failures, 0 repeated cursor writes, and 0 fast-path decision mismatches. It observed 209 immediate opens and 9 intentional Vanilla fallbacks caused by a queued offhand action.

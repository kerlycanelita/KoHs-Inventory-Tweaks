## Fixes

### The highlighted slot and the slot that takes the click

Minecraft cuts the pointer to whole GUI pixels before it draws a screen, and
every slot edge sits on a whole pixel, so the slot it highlights is always the
slot a click at that pointer takes. The GUI Scaler converted that cut pixel to
the scaled inventory and rounded it, which near every slot edge highlighted one
slot while the click, F, 1-9 or Q went to its neighbour. It now converts the
exact pointer and cuts afterwards, as Minecraft does.

The `hover-agreement` lab walks the pointer across every column and row edge of
the player inventory a screen pixel at a time and compares the highlight each
frame drew with the slot a click there would take: 63 disagreements in 560 on
1.1.1, none on 1.2.0, on 26.2, 26.1.2, 26.1.1, 26.1 and 1.21.11.

### Center Mouse Fix in one move

GLFW puts the pointer back where it saved it when the mouse was captured as it
leaves disabled mode, after Minecraft has asked for the centre. Center Mouse Fix
used to read the pointer back afterwards and correct it. It now leaves disabled
mode first, so the request Minecraft makes moves the visible pointer, and nothing
reads or rewrites the pointer once the inventory exists. On Wayland, which
cannot place a free pointer, the release stays as in Vanilla.

### Player Visibility with a transparent backdrop

With the inventory backdrop at 0% there is nothing to reveal, so the
line-of-sight checks for the reveal windows no longer run. With a backdrop they
stop as soon as the nearest visible players are found.

## New options

All of them are on the Inventory Tweaks page; each one explains itself when
hovered. Nothing here clicks, moves or sends anything for the player.

| Option | Default | What it does |
| --- | --- | --- |
| Shortcuts follow the pointer | On | Number keys, F and Q act on the slot under the pointer the moment they are pressed. Off: the slot highlighted in the last frame, as in Vanilla. |
| Pixel-perfect scale | On | The GUI Scaler uses whole screen pixels per inventory pixel, so slots stay even and sharp. |
| Steady tooltips | Off | Tooltips wait 0.15 s after the pointer reaches a slot. |
| Recipe book lock | Off | A closed recipe book loses its button, so a missed click cannot shift the slots. |
| Totem protection | Off | The offhand key, a number key over the offhand slot and the drop keys never take a totem out of the offhand or throw one. |
| Empty-slot swap warning | On | With a totem in the offhand, an empty slot under the pointer turns crimson; violet when Totem protection blocks the swap. |
| Held slot marker | On | Brackets the hotbar slot in hand. |
| Key hints | Off | Keycaps with the key of each hotbar slot and of the offhand. |
| Durability readout | Off | Durability left on damaged items, in percent. |
| Inventory totals | Off | Item tooltips add how many of that item you carry. |
| Slot change flash | On | A slot glints when its item changes. |

## Verification

- `features` lab on every version: totem protection declines the swap, the
  hotbar swap and the drop, confirmed against the integrated server, and the
  same swap goes through with the protection off; plus pixel-perfect sizes at
  GUI scale 2, 3 and 4, the recipe book lock, steady tooltips, inventory totals,
  key labels and the shortcut target switch.
- `overlay-perf` on 26.2: about 26 µs of render-thread time per frame with
  every overlay on; frame rate within noise.
